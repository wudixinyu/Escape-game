## 搭「解脱」的第一个可跑框架

起点：仓库里只有 `project.godot` 和一个 icon，空白项目。

按用户给的方向落地（出牌顺序 + 2D + 休闲解谜，Control 而非 Area2D）：

- `core/` 三个文件把规则彻底数据化。关键设计：**每张牌出牌后自动把自己的 id 当作一枚标记投放**，
  于是 `requires` 里可以直接写卡 id，解锁和「解脱」共用同一套标记表达式，不需要再区分
  「被谁点名」和「条件满足」两套机制。
- 三种目标（释放 / 清除 / 接引）共用一条流程：出牌 → 投放抹除标记 → `_settle()` 循环到稳定 → 判定。
  `_settle()` 反复跑是有意的：让「最后一张牌自己也散去」这种写法成立（它 grants 的标记满足自己的
  `liberated_by`）。
- 卡死检测：`max_missteps`(仅接引型) + 「无牌可出」，两种都走 `deadlocked` 信号，逼客户端走重来。
- 三个示例关卡写在 `levels/LevelLibrary.gd`，每关都配了「错序会怎样」：
  1. 解封 —— 撕符会永久阻塞目标，但留了「净露」补救路径
  2. 度尽 —— 静水必须在「缠/焚」出现之后才有用，先浪费掉就再没第二次
  3. 引渡 —— 三张无用牌，出满三张雾就合拢

## 验证过程中的四个坑（已写进 skill）

3. autoLoad 在 `--script` 模式下 `_ready` 不一定被调用 → 关卡数据放 `_init()`。
4. 三个无头测试专属陷阱：lambda 按值捕获（信号回调改不了外层变量）、
   `add_child` 后 READY 延后一帧（会导致「桌面空无一物」且不报错）、
   `await` 会把控制权还给调用者（外层必须 `await helper()` 才不会提前打印总结）。

结果：`--headless --script res://tests/TestEngine.gd` 16 项全通过，`--quit-after 240` 无运行期报错。

## 新增第四～六关（全部只改数据，规则引擎一行没动）

一夜之间从 3 关变 6 关。关键收获是**三种设计机关在纯标记系统里怎么成立**：

- **第四关「燃犀」· 释放型 · 单向门**：`燃犀` 是全桌唯一产出「明」的牌，`熄犀` 唯一产出「暗」
  且唯一能把「明」抹掉。正解必须先在光下走完 `照见 → 超度` 把「形」送走，再熄灯 `循声` 摸「影」。
  错序必死 —— 因为被锁死的 requires 不会再开，且没有第二张牌能把「暗」收回去。
- **第五关「澄心」· 清除型 · 不必出手的牌**：`妄念` 写 `requires: ["__never__"]`，
  永远封印、永远点不动，却照样会被 `liberated_by: ["尽心"]` 带走。
  这是本作第一次出现「玩家碰不到但会自己解脱」的牌；`搅 / 沉淀` 是唯一的陷阱与解药对，
  其余家务牌（叠衣等）全部 `liberated_by: ["尽心"]`，最后一步一起散场。
- **第六关「问津」· 接引型 · 四站**：`忘川` 抹掉「认」，而 `渡舟` 要同时凭「资」和「认」才开 ——
  抹早了就得靠 `重相识` 花一步认回来，两步滞涩正好用光 `max_missteps: 2` 的容错。

第一次写第四关时踩了坑：给了 `复燃`（clears 暗、grants 明）当补救，于是**所有顺序都能通关**，
关卡等于没有约束。教训写在 skill 里：**只要出错之后存在一张能把 blocker 收回去的牌，
这个顺序约束就不成立**；单向门必须让「收回」这件事本身没有第二张牌可做。

另外发现两件事，值得记住：

1. **死局是「没有牌可出」那一刻才判的**。写「错序会死」的测试时必须把还能出的牌出到底
   （加了 `_exhaust()` 辅助），否则断言假阴性 —— 我第一版测试就是这样误判的。
2. `tools/SnapPreview.gd` 原来写死 `for i in 3`，加关就静默漏截；已改成读 `Game.levels.size()`。

验证：`--import` 无错、TestEngine **37/37**（新增 3 组定向用例：单向门两种错序、不可触碰牌、
忘川补救路线含滞涩数断言）、`--quit-after 240` 无告警、六关 + 主界面截图全部正常排布
（第五关 10 张排成 8+2，第二排正好是「搅 / 沉淀」这对陷阱与解药）。
占位素材补了 26 张（共 48 张卡），已有的 22 张真素材未被覆盖。
